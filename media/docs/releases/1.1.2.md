# amigaux 1.1.2 — release notes (draft)

> **Status: draft.** The package versions are those of the 1.1 repository's tree at the time of
> writing; the final ones, the files' sizes and sha256, and the "Tested" rows are added from the
> build of record. Until then the numbers below may change.

1.1.2 is a point release in the 1.1 package repository (`http://pkg.amigaux.org/1.1`). It brings
new kernels on both lines (68030-261115-78 on the 68030, 68060-261115-67 on the 68040/68060), a
driver for the MNT VA2000, the MNT ZZ9000 as an RTG card beside the Z3660's own, and updates to
the X-Surf driver, kbootset, amix-base, X11R6.3 and apkg. A 1.1 or 1.1.1 system takes 1.1.2 in
place with `apkg`; nothing is reinstalled.

## New in 1.1.2

- **MNT VA2000 RTG graphics** (packages `va2000-k30` and `va2000-k46`, version 1.1.0-1): the card
  as `/dev/va2000`, for the X server Xrtg of X11R6.3. The module loads at the first open of
  `/dev/va2000` and stays only when it finds a board. The console stays on the Amiga's own
  display. The page is va2000(7).
- **MNT ZZ9000** (packages `z3660rtg-k30` and `z3660rtg-k46`, version 1.1.2-1): a ZZ9000 in
  Zorro II or Zorro III as an RTG display, `/dev/zz9000` alone or `/dev/zz9001` beside a Z3660,
  with the card files `zz9000` and `zz9001` for `xstart` (display.d(4)). A Zorro III ZZ9000 lies
  above 1 GiB, which the new 68030 kernel takes. The page is zz9000(7).
- **The X-Surf driver** (packages `xsurf-k30` and `xsurf-k46`, version 1.0.0-4): the board's
  station address read through its data path, and the tool `xsf` (xsf(1M)) to show the link and
  the board's readings.
- **kbootset 1.1.0.261115-46**, which knows the VA2000's character major.
- **amix-base 1.0-36** (1.1.1 had 1.0-34):
  - `shutdown` asks init through the new `initwait` (initwait(1M)): it waits up to 30 s for the
    run level `who -r` shows to change, asks once more if it has not, and after another 30 s
    says the system has not changed state. It never halts the machine itself. `man shutdown`
    shows initwait(1M). The stall it does not cover is under "Known issues".
  - `xstart` ends an X server that xinit left running when xinit was killed, then restores the
    card and switches the monitor back; before, it ran the restore with X still on the display.
  - A display card file may name a probe that tells whether its board is there (display.d(4)).
    `xstart` only warns about keys it does not know, and `xstart -n` refuses only a mistake in
    `/etc/display` or in the card in use.
  - interfaces(4) names the interfaces the system has (zen0, aen0, xsf0/xsf1, lo0).

## Installing them

```sh
apkg update
apkg upgrade
apkg install va2000-k46      # or va2000-k30, with a VA2000 fitted
```

`apkg upgrade` installs the new kernel of your line, kbootset and the updated packages, then
builds and commits the boot generation (or prints the command, with `bootset=manual`). Reboot to
start the new kernel.

## The installer and the media

The 1.1.2 media replace 1.1.1's, with the same installer. Every installed system now carries the
VA2000 driver beside the Buddha and X-Surf drivers; it costs nothing on a machine without the card,
as it loads only when `/dev/va2000` is first opened.

- **The install CD** (`amix-1.1.2-install.iso`), **the boot floppies**
  (`amix-1.1.2-boot-k30-1.adf`, `-2.adf`; `-k46-`), **the Z3660 boot disk**
  (`amix-1.1.2-boot-z3660.hdf`) and **the network installer** (`amix-1.1.2-netinstall.iso`)
  install onto the same disks and controllers as 1.1.1's.

## Tested

- **VA2000:** the install and a boot with the module in the boot set, in emulation, with no board
  present; the VA2000 cannot be emulated, so not on a real card.
- **ZZ9000:** in emulation (a ZZ9000 in Zorro II); not on a real ZZ9000.

## Known issues

- **`shutdown` can give the prompt back while the machine halts only minutes later, or not at
  all** (the stock `/sbin/init`; measured in emulation on the 68030 kernel with 16 MB, not seen
  on 32 MB so far; the 68040/68060 line runs the same init). After heavy file writing on a
  machine short of memory, init can stall in one of two ways. Do not switch off on the prompt:
  wait until the console says `The system is halted`.
  - **The run level never changes** (`who -r` still shows the old one): init missed the
    request, and on its own would act on it only when its five-minute timer wakes it.
    `shutdown` sees this and asks once more after 30 s; a second request is acted on at once.
  - **The run level changes but the shutdown scripts never start** (`INIT: New run level: 0`
    is shown and `who -r` says run level 0, then nothing more happens): init waits for the
    child that printed the new level to end, though that child is already gone; why is not
    known. Seen so far only on the 68030 kernel with 16 MB, after heavy writing. `shutdown` does
    not see this, and neither a second request nor `kill -ALRM 1` ends it. The halt sometimes
    goes on by itself after minutes. If it does not, type `sync`, wait until the disk has gone
    quiet, and switch off; the file systems are checked at the next boot.
- **One program's data and address space are not limited; its stack is limited to 16 MiB**
  (the kernels of 1.1, 1.1.1 and 1.1.2, both lines; the 1.1 notes said 16 MiB soft limits
  until they were corrected). The soft and hard limits of data and address space are unlimited.
  `ulimit -d` and `ulimit -v` with a size in KiB set a limit for a shell and what it starts. A
  later kernel brings the stock 16 MiB soft limits of data and address space back as the default.
- The other known issues of 1.1.1 apply unless a line above says otherwise.
