# amigaux 1.1.1 — release notes (draft)

> **Status: draft.** The files' sizes and sha256 are added from the build of record (make dist on
> the release line), with the acceptance rows; until then the numbers below are left out.

1.1.1 adds two drivers to amigaux 1.1, as packages in the 1.1 package
repository (`http://pkg.amigaux.org/1.1`). The kernels are 1.1's (68030-261106-77
on the 68030, 68060-261106-66 on the 68040/68060), and every 1.1 package is
unchanged but kbootset, which the new drivers need. A 1.1 system takes 1.1.1 in
place with `apkg`; nothing is reinstalled.

## New in 1.1.1

- **Individual Computers Buddha and Catweasel Z-II IDE** (packages `buddha-k30`
  and `buddha-k46`, version 1.1.0-4). The Buddha's two IDE ports and the
  Catweasel Z-II's three (how far the Catweasel is tested: see "Tested"), with
  disks and ATAPI CD-ROM drives, master and slave, as SCSI disks under `sd`. It loads before the root is mounted, so the root
  can be on a Buddha disk. Interrupt I/O by default after a self-test at boot;
  if the test fails, or the interrupts stop later, it goes on polled.
  `param intr=0` in `/etc/conf/modreg.local.d/buddha` selects polled I/O from
  the start. The SCSI units are fixed per port and drive: 6 and 5 on the first
  port (master, slave), 3 and 2 on the second, 1 and 0 on the Catweasel's
  third.
- **Individual Computers X-Surf-100 and X-Surf ethernet** (packages
  `xsurf-k30` and `xsurf-k46`, version 1.0.0-2). The interface is `xsf0`
  (then `xsf1` for a second board); configure it in `/etc/inet/interfaces`
  like any other. The X-Surf-100 works in Zorro II and Zorro III mode, the
  X-Surf in Zorro II.
- **kbootset 1.1.0.261114-45**, which knows both drivers: the Buddha's
  board, and the X-Surf's character major.

## Installing them

First bring kbootset up to date, then install the driver for your kernel's
line (`-k30` on a 68030, `-k46` on a 68040 or 68060):

```sh
apkg update
apkg upgrade
apkg install buddha-k46      # or buddha-k30
apkg install xsurf-k46       # or xsurf-k30
```

`apkg upgrade` installs kbootset 1.1.0.261114-45. The drivers need it (the
Buddha 1.1.0.261113-44 or later); with an older kbootset the new boot
generation is refused and the one before it stays and still boots. After the
install, apkg builds and commits the boot generation (or prints the command,
with `bootset=manual`). Reboot to load the driver.

**Moving the root disk to the Buddha.** A disk that boots from the A4000's
IDE port, or any other controller, still names that controller in its boot
generation when it moves to the Buddha. Before the move (or after it, from a
boot that mounted the root), run `kbootset cards` for the new controller's
key, then `kbootset build` with that key as the boot and root device and the
disk's root on it, then `kbootset commit` (the swap follows the root: it is
slice 2 of the root disk). The steps and the exact
arguments are in "A disk moved to another controller" in the kbootset
documentation (`kernel/dlm/docs/contracts/C2-4-kbootset-cli.md`, section 6,
in the amix repository).

## The installer and the media

The 1.1.1 media replace 1.1's: the same installer, which now also knows the new
controllers, and the same RAM-disk boot.

- **The install CD** (`amix-1.1.1-install.iso`) installs onto a disk on any
  controller 1.1 took (the Z3660's SCSI, an A4091 or A4092, the A3000's and the
  A4000T's SCSI, the A4000's or A1200's IDE port) and now onto a disk on a
  Buddha, master or slave on either port. The interview lists the Buddha's disks
  as "Buddha IDE". The installed system's boot generation names the Buddha by
  its board id and the disk's unit, so the disk boots wherever Kickstart placed
  the board; with two boards of one kind it also names the root board's address.
  The CD can sit on the Buddha too. A Catweasel Z-II's disks are offered the
  same way, as "Catweasel Z-II IDE" (tested in emulation on the 68040/68060
  line).
- **Every installed system** carries both new drivers in its boot generation,
  whatever its controller: a Buddha fitted beside the root's controller is
  driven, and an X-Surf comes up as `xsf0` by DHCP through the
  `/etc/inet/interfaces` line `* dhcp`. The first-boot dialog lists `xsf0`
  among the interfaces it finds, so an X-Surf can also take a static address.
- **The boot floppies** (`amix-1.1.1-boot-k30-1.adf`, `-2.adf`; `-k46-`) and
  **the Z3660 boot disk** (`amix-1.1.1-boot-z3660.hdf`) boot the installer
  with the Buddha's driver loaded, so a disk on a Buddha is offered from them
  as from the CD.
- **The network installer** (`amix-1.1.1-netinstall.iso`) has the same
  installer and the same targets, and it can also install over an X-Surf: the
  interfaces it offers are the Z3660's (`zen0`), the A2065 (`aen0`) and the
  X-Surf (`xsf0`), each with a static address, as in 1.1.

## The ready installed disk images

Each image is the x11 set installed in emulation and halted before its first
boot, so the first boot asks for the name, the network and the passwords. Each
carries both new drivers in its installed system and its boot generation.

| File | For |
|---|---|
| `amix-1.1.1-k46-4g.zip` | the Z3660: SCSI unit 6 (3600 MiB) |
| `amix-1.1.1-k30-4g.zip` | a disk at SCSI id 6 on the A3000's own SCSI controller (3600 MiB) |
| `amix-1.1.1-k46-ide-2g.zip` | the IDE master of an A1200 or A4000 with a 68040 or 68060 (1800 MiB) |
| `amix-1.1.1-k30-ide-2g.zip` | the IDE master of an A1200 or A4000 with a 68030 (1800 MiB) |
| `amix-1.1.1-k46-buddha-2g.zip` | **new:** the first port's master of a Buddha, in a machine with a 68040 or 68060 (1800 MiB) |
| `amix-1.1.1-k30-buddha-2g.zip` | **new:** the first port's master of a Buddha, in a machine with a 68030 (1800 MiB) |
| `amix-1.1.1-z3660-sd-kit.zip` | setting up a Z3660 card from scratch, with the 1.1.1 boot disk and 68060 system |

A Buddha image written to another position on the Buddha (the first port's
slave, or the second port) boots once its boot generation names that unit:
from AmigaOS, write it to the first port's master instead; or, from a boot that
mounts its root, follow "Moving the root disk to the Buddha" above with the new
unit.

## Tested

Both drivers are tested in emulation only (Amiberry), not on real cards.

- **Buddha:** on both lines with the released packages: the root on the first
  port's master, on a lone slave of the first port, or on the second port's
  master; a second data disk beside a root on the Gayle IDE; an ATAPI CD-ROM
  read through cdfs on the first port's slave and on the second port, on both
  lines; an empty board (no cost at boot); interrupt I/O, and the change to
  polled I/O when the interrupts stop.
- **Catweasel Z-II:** tested in emulation on the 68040/68060 line: the root
  on the first and on the third port, a data disk on the third port, an ATAPI
  CD-ROM, interrupt I/O. Not tested on a real card.
- **X-Surf-100 and X-Surf:** in emulation on both lines, on the released 1.1
  kernels.

## Known issues

- **68030 with an X-Surf-100 in Zorro III mode.** The card's maker requires
  that a 68030 does not use its data cache for the card in Zorro III mode.
  The 68030 kernel runs with the data cache off in supervisor mode, where
  the driver does all its accesses, so the rule holds; the driver never maps
  the card into a program.
- **A late halt on a 16 MB machine** (both kernel lines; not new in 1.1.1).
  After a lot of disk writing on a machine with 16 MB, `shutdown` may print its
  messages and return to the prompt while the system keeps running; it halts by
  itself within five minutes. Do not switch off until the console says the
  system is halted. If `who -r` still shows the old run level half a minute
  after the shutdown, type `/sbin/init 0` (or `/sbin/init 6` for a restart)
  once more; the system then halts at once.
- The other known issues of 1.1 apply unchanged.
