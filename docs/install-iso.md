# The Amix 2.1 install CD

The install disc is the package source the installer reads from: the same apkg
catalog + package tree the HTTP repo serves (`../amix-packagemanager`), mastered
onto a single-session Rock Ridge ISO.

    /catalog            apkg catalog v1 (generated by amix-packagemanager gen-catalog.py)
    /catalog.md5        its md5
    /pkgs/stock/*.pkg   the 27 repackaged Amix 2.1 factory packages   (Commodore)
    /pkgs/base/*.pkg    our apkg client + heirloom engine             (ours)
    /install/           installer payload staged by tools/build-install-iso.sh:
                        bin/ (static pkg engine, SVR4 sum, install.sh + firstboot),
                        admin/, order, profiles/*.profile, boot/<profile>/ chain
                        (bootslice.img + boot2.boot + manifest)   (see docs/installer.md)
    /MANIFEST           what the disc is (content set, every package, classification)
    /LICENSING          release status (cleared 2026-09-23) + publication record

## Builder — `tools/build-iso.sh`

Single-session, Rock Ridge on, Joliet off, no `.Z`, no spaces in any pathname
(see the header of `tools/build-iso.sh` and `tools/lib/isocheck.py` for the full
rationale — every constraint corresponds to a way an Amix cdfs read misbehaves
*silently*). `--self-test` masters synthetic discs and proves each hard constraint
FIRES (16/16). The builder verifies the finished image against the constraints by
reading the MASTERED artifact back, not by trusting the mkisofs flags.

    tools/build-iso.sh --set full          # all 27 stock + our base/ -> work/iso/
    tools/build-iso.sh --self-test         # prove every constraint fires

The PVD System ID stays blank. The A4091/A4092 ROM (`a4092_cdfs.rom`, CD boot on by
default) boots a data CD whose System ID reads `CDTV` or `AMIGA BOOT` at priority 2,
above the installer's UNIX_Boot (1); any other disc gets -1. `check_blank_system_id`
refuses a disc that carries one.

The ISO is a build artifact and is **never committed**: `work/` (the default
output dir) is gitignored, and build-iso.sh's own Gate 1 refuses to write the
image to any path git would track. Publishing a built disc is a per-artefact
owner decision, recorded on the disc (see Gate 17). (A blanket `*.iso` ignore was deliberately NOT added:
it would make every `.iso` path gitignored and thereby defeat that Gate 1
refusal — the disc must be corralled to a gitignored location, not scattered.)

## Gates against a BUILT ISO

These re-prove, on the finished artifact, the properties the installer depends on.
Each is fail-closed (a skip or an operational error is never reported as a pass) and
callable standalone. build-iso.sh already runs the equivalent checks INLINE during a
build; the standalone gates are for verifying an image after the fact / in CI.

### Gate 9 — `tools/iso-name-gate.py` (name mangling)

The ISO/RR name space must be *exactly* the staged names, or the catalog's
`filename` lookups miss silently. Checks: no path component over `ODFS_NAME_MAX`
(512 on Amix — the 128 cap is the AmigaOS platform only), no spaces, no
same-directory case-collision, and — with `--staged` — ZERO `~2`/`~3` collision
renames (on-disc names == staged names). Logic is `tools/lib/isocheck.py`, reused.

    tools/iso-name-gate.py <iso> --staged DIR   # DIR = build-iso.sh --keep-stage tree
    tools/iso-name-gate.py --self-test          # every check demonstrated firing

Without `--staged` the authoritative zero-rename cannot run, so the gate returns
non-zero (INCOMPLETE) rather than a green — a skip is not a pass.

### Gate 17 — `tools/licensing-gate.sh` (release stamp)

> **History:** until 2026-09-23 this gate enforced a private-only invariant (stock
> content ⇒ disc stamped not-for-redistribution, `--redistributable` refused). The
> restriction was lifted 2026-09-23 (Amiga Corporation approved distributing the
> Commodore Amiga binaries); the private-only stamp was retired 2026-09-26.

Invariant: **stock content present ⇒ `/LICENSING` carries the stamp
`release-cleared 2026-09-23`, `/MANIFEST` carries a well-formed `publication:` line
(`unpublished …` or `published by owner decision YYYY-MM-DD`), and — if the image
lives in a git work tree — it sits on a gitignored path.** A disc still carrying the
retired stamp is refused with a "rebuild" message.

    tools/licensing-gate.sh <iso>          # verify a built ISO's release stamps
    tools/licensing-gate.sh --self-test    # 4 mis-stamped discs refused, 3 controls pass

build-iso.sh writes the stamps at BUILD time. By default a disc is stamped
`publication: unpublished`: **publishing any medium is a per-artefact owner
decision**, and the tools never publish or copy anything. When the owner decides to
publish a specific medium, rebuild it with `--published-by-owner YYYY-MM-DD` so the
disc records that decision; the date must be well-formed. `--redistributable` is
retired (it now exits 2 pointing at the new flag). Gate 1 — never write the image to
a git-tracked path — is unchanged: media are never committed.

### Gate 8 — source↔catalog consistency (amix-packagemanager tooling)

Regenerate the catalog from the ISO's OWN packages with the canonical generator and
confirm it matches the shipped catalog byte-for-byte:

    xorriso -osirrox on -indev <iso> -extract /pkgs   <tmp>/pkgs
    xorriso -osirrox on -indev <iso> -extract /catalog <tmp>/catalog
    cp ../amix-packagemanager/build/repo-staging/deps.conf <tmp>/pkgs/deps.conf
    mkdir <tmp>/regen
    python3 ../amix-packagemanager/tools/repo/gen-catalog.py <tmp>/pkgs -o <tmp>/regen
    diff <tmp>/catalog <tmp>/regen/catalog        # identical == consistent

## E1 — CD read throughput (EMULATED)

Measured 2026-07-22 on the bench: Amiberry (repo build), 16 MB Amix 2.1c guest,
idle. **This is the EMULATED figure; the metal number waits for a real burn
(Wave 6).** Method: `timex cat <path> > /dev/null` on the box (cold read; the 16 MB
guest cannot cache a 60 MB file), MB = decimal (÷10^6), MiB = binary (÷2^20).

| read                                | bytes       | real (s) | throughput            |
|-------------------------------------|-------------|----------|-----------------------|
| largest package (X11r5src-2.1.pkg)  | 62,920,704  | 11.03    | 5.70 MB/s (5.44 MiB/s)|
| whole `/cdrom/pkgs` tree (29 files) | 298,023,424 | 51.36    | 5.80 MB/s (5.53 MiB/s)|

`user` time was ~0 and `sys` ≈ `real` on the idle box: the read is kernel/cdfs-bound
(emulated SCSI DMA), not CPU-bound. The install ISO built from the full 27-package
set is 298,434,560 bytes (285 MiB), so a whole-disc read is ~52 s emulated.

Medium verified end-to-end the same session: `mount -F cdfs 1,3 /cdrom` (the first
mount after an INSERTCD swap fails errno 5 / unit-attention — re-insert and mount
again), `ls /cdrom/pkgs/stock | wc -l` = 27, and `sum -r` of `uucp-2.1.pkg` on the
box matched the host checksum (`07632`; SVR4 `sum -r` counts 512-byte blocks vs
GNU's 1024, so only the block column differs).

## The boot disk of a CD install — `tools/build-boot-hdf.sh`

A CD-sourced install on a machine that cannot boot the miniroot from floppy (the
A4000D + Z3660 060, profile `metal-a4000-z3660-060-a4092cd`, CD-1) boots from a
small disk instead: slice 1 the proven UFS install miniroot, slice 2 the structural
swap placeholder, slice 3 the boot chain. There is no payload; the packages come
from the CD.

    tools/build-boot-hdf.sh --profile metal-a4000-z3660-060-a4092cd --dry-run
    tools/build-boot-hdf.sh --profile metal-a4000-z3660-060-a4092cd --out work/boot-hdf/<name>.hdf

Before it writes anything, the tool checks the reused miniroot against this disk:

- its first cdfs probe must be the profile's `CD_SPEC`;
- every baked RAW candidate must sit on card 0, at the boot disk's own unit, on a
  slice the disk does not have;
- no candidate may be on card 1. A card-1 candidate turns the disk scans card-1,
  and a `dd`-layer read of a CD unit behind an A4091/A4092 wedges that bus.

The kernel must match its kerntools `MANIFEST.json` row (sha256, rootdev, `sum -r`).
While the profile's `SRC_KERNEL_BREL_SUMR` reads `PENDING`, the build stops at the
kernel step. Framing and the round-trip gate are `write-bootchain.py`'s, as in
`build-raw-source.sh --bootable`.
