# amigaux 1.1 — release record (draft)

> **Status: draft.** No cut of record yet. The 1.1 set is frozen from amix `make dist` output at one commit; the
> media of record, their hashes and the acceptance evidence are added here then. Until that, this file collects the
> known limits found on the way.

The 1.1 install is a clean install from packages (`docs/installer.md`, "The 1.1 install from packages — current";
the disk: `docs/l11-disk.md`). There is no upgrade from 1.0. From 1.1 on, later releases upgrade an installed 1.1
system in place (its packages, through apkg); 1.1 is the last release that installs only from scratch.

## New in 1.1

- **`/dev/audio` is now present** (the stock Paula sample-stream driver, mode 0660 root audio), with three of its
  stock defects fixed: a request with no data no longer panics the kernel, each volume or speed request is answered
  once, and a long write plays once.
- **The installer with more than one disc or a used disk.** It takes only an amigaux 1.1 install disc for the
  machine's processor line: another disc in a second drive is named and skipped, and when two 1.1 discs answer it
  lists them with their build dates and asks which. It offers a disk's own size, not the size of the layout already
  on it, so a reinstall over a smaller layout gets the whole disk. Two cases keep the old layout's size, and the
  installer says so: the A3000's own SCSI controller, where the size cannot be read safely, and a disk on a third or
  fourth disk card (the IDE port beside a Z3660 and a Zorro SCSI card, for example), which the stock size tool
  cannot reach. A disk with no layout on it has its size asked. The set menu shows each set's whole size, the base
  packages it brings included (x11, "Everything on the disc", is 150.8 MB), and a root too small for the chosen set
  is refused before anything is written, with the root size that holds it and the choice of a new size or a smaller
  set (an x11 install on a 104 MB root used to stop at its end with "file system full").

## Fixed in 1.1: bugs inherited from Amix 2.1c and present in 1.0

These came with Amix 2.1c and are still in amigaux 1.0. The 1.1 kernels (68030-261106-77 on the 68030,
68060-261106-66 on the 68040/68060) and packages fix them. There is no update from 1.0 (see above), so a 1.0
system keeps them until it is installed afresh with 1.1.

- **Files: a large file rewritten in place could read back wrong while memory was short.** The data on the
  disk stayed right; what a program read back could be wrong, and the disk was wrong too only if a program
  wrote back what it had read (vim's swap file did that). Until you move to 1.1, don't rewrite large files in
  place on a machine short of memory.
- **Files: writing into the middle of a sparse file could expose old disk contents**, including the data of
  deleted files.
- **68030 only: a machine short of memory, 16 MB in particular, could hang**, most often during a network
  install.
- **68040/68060, SCSI disks: reading past the end of a slice could hang the program** so that it could not be
  killed.
- **FTP: a download from an Amix server could lose its last bytes**, though the server reported the transfer
  complete (226). Fixed by the ftpdfix package.

## Known limits

- **A file system holds at most 2047 MiB** (4,194,303 blocks). A 2047 MiB ufs slice makes, fills and reads back; at
  2048 MiB `mkfs_ufs` fails in `wtfs` with ENXIO (the driver's raw-I/O clamp), at 3072 MiB with EINVAL (a 32-bit
  seek). The installer refuses a larger root (and caps the data slice); on a bigger disk, make more partitions.
  Measured on the 68060 line; on the 68030 line nothing past 2 GiB of a disk is tested.
- **Swap: the memory programs can use is the swap size**, whatever the RAM (stock Amix behaviour). The installer
  now offers a swap partition by memory: 64 MB on a machine with less than 32 MB, 128 MB with 32 MB or more,
  never more than a quarter of the disk (and at least 30 MB on the 68040/68060). One swap area can be only as
  large as the kernel takes with that much memory (on the 68030 about 192 MB with 16 MB, 384 MB from 32 MB; on the
  68040/68060 far more); a larger answer gets a warning and an offer of that size, but is kept if you say so.
  Every boot adds the whole partition, or as much as the kernel takes, and says so on the console when it is
  less. For more swap, make a file `/SWAPFILE` (for example `dd if=/dev/zero of=/SWAPFILE bs=1024k count=64`):
  every boot adds it. `swap -a` adds swap only until the next reboot; `swap -l` shows what is in use.
- **A file over 256 MiB needs the login `ulimit` raised**; amix-base sets 4194303 blocks in `/etc/default/login`.
- **One program gets 16 MiB of data and of address space by default**: the stock soft limits are kept. A big job,
  such as gcc on a very large source or an rsync of all of `/usr`, needs them raised in its shell first:
  `ulimit -d unlimited` and `ulimit -v unlimited` (or a size in KiB). The hard limits are unlimited, so any user can
  raise them, for that shell and what it starts. X is not affected: `xstart` sets its own.
- **Stock `/etc/rdb -V` shows a slice of 2 GiB or more with a negative size in bytes** (the 1991 tool's 32-bit
  arithmetic), for example when the installer lists a disk it is about to erase that already holds a large 1.1
  layout. The block counts on the same line are right; only the display is wrong.
- **A second disk on the A3000's own SCSI controller** stopped Kickstart 3.2 from booting the first disk in
  emulation (a 9.4 GiB and a 3.9 GiB second disk). No route for adding a second disk is tested yet.
- **The 68030 pre-installed image is accepted in emulation only**; the 68060 image gets one boot on real hardware
  before release.
- **Boot priority.** The installer makes the new disk's boot slice bootable at priority 2, the stock value.
  Kickstart boots the bootable partition with the highest priority on any disk, so an AmigaOS disk at the usual 0
  loses to the new install, but any other bootable partition above 2 wins: an older Amix install, a disk behind an
  A4091/A4092 or on the Z3660, a boot disk used for the install. What you see: the machine boots the other Amix
  disk (or the other system) instead of the new one. Lower that partition's priority or raise the new disk's
  (HDToolBox, or the Early Startup menu for one boot), or take the other disk out of the boot. A disk used only to start the install (the RAM-disk boot disk, priority 5) must leave
  the boot before the installed disk's first boot.
- **Installing to the A4000's IDE disk with other SCSI cards fitted.** The kernels number the disk cards by kind
  (the Z3660, then Zorro cards, then the motherboard SCSI, then the IDE port), so the IDE port is card 0, 1 or 2
  depending on what else is fitted. The installer reads the card from the running kernel and installs to the IDE
  master; the CD may be on the IDE slave. A disk at SCSI id 5 on another card is not offered as a target, because
  the CD search uses unit 5 of every card.
- **Kernel inspection tools.** The stock `/usr/sbin/sysdef` reads `/etc/master.d`, the static kernel's
  configuration, and stops with "/etc/master.d not a directory": on 1.1 the drivers come from modules, so there is
  none. Use `modadmin -s` for the running set and `kbootset status` for the booted generation.
  On the 68040/68060 kernel, `crash` does not work: it checks every kernel address against 68030 page tables that
  this kernel does not keep, and stops with "<addr> is an invalid address" (on `/dev/kmem` too: the check runs
  before any read); use `modadmin -s`, `kbootset status`, `ps` and `sar` instead. `adb -k` there reads the kernel's own variables
  (its .data and .bss, below 0x40000000) correctly, but addresses at or above 0x40000000 (the kernel heap, kvseg,
  the u-area) are translated with 68030 logic and can show wrong values; read those through `/dev/kmem` directly.
  On the 68030 kernel, `crash`'s `od` of a virtual address ends in a segmentation fault
  (inside crash's own address translation); use `od -p`, the physical form: the kernel's own data lies below
  0x40000000 and is identity-mapped, so a variable's namelist address is its physical address. Give it by name
  (`od -p -x ninode 1`) or as bare hex without a leading zero (`od -p -x 70d7e3c 1`; crash reads a leading 0 as
  octal and 0x as a symbol name). This does not reach kernel addresses at 0x40000000 and above, such as the tables
  those variables point to; the table commands (`p`, `inode`, ...) work.
- **The package repository is reached by name** (`pkg.amigaux.org`; no address is stored, because the host may move).
  A fixed-address install with no name server (DNS answered no at the first boot) does not reach it, or set its clock,
  until it has one: add a `dns` line to `/etc/inet/interfaces`. `apkg` says it cannot resolve the name, and
  `/var/adm/rc.log` says so for the clock at each boot; `ntp_servers` in `/etc/rc.conf` takes addresses too.
- **A network install finishes at the first boot.** The first boot fetches the rest of the chosen set from the
  package repository before the login prompt appears. Over the internet the full set can take more than an hour
  (65 minutes to the login prompt, measured); the standard set takes much less. Let it run.
- **Sockets, for programmers: two defects of the stock libsocket** (measured on the 68030 and 68060 kernels).
  A program that peeks (`recv` with `MSG_PEEK`) at a listening socket can no longer accept on it: every later
  `accept` fails with EINVAL; don't peek at listeners (`poll` and `select` on them are fine). A non-blocking `send`
  that meets a nearly full socket reports all its bytes as sent and drops what did not fit (with no room at all it
  fails with ENOMEM, not EAGAIN); on non-blocking stream sockets use `write(2)`, which returns the count that went
  and EAGAIN. Blocking sends are not affected. Python and programs built on GNU Pth (pth 2.0.7-3) are not affected.
- **TCP: a program that closes a socket right after writing can lose the data not yet sent** (the stock
  kernel's close). This includes uploads made with the stock `ftp` client from Amix. For programmers:
  `shutdown(fd, 1)`, read to end of file, then `close`. A kernel fix is planned after 1.1.
- **`setclk -p` prints the year as three digits** from 2000 on (2026 shows as 126); the clock itself is right.
- **X on the Z3660's RTG needs X11R6.3** (the x11 set from the install disc, the full set over the network, or
  `apkg install x11r6.3`); on a standard install `xstart` uses the native display.
- **CD filesystems:** the cdfs kernel module is installed on every disk and loads at the first CD mount, so a
  box without a CD drive spends no memory on it.
