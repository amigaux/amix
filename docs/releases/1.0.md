## Known limits

- **A CD install needs a 200 MB disk or larger** (set 1, standard). On the 100 MB default disk standard runs out in Xcore, because pkgadd also
  spools each package into the target's /tmp; the installer stops and leaves the disk unarmed. 200 MB passes
  (cd-std200-pub-r6). A pre-install size check is on the 1.1 list.
- **Memory (classic kit):** the emulator configs ship with 64 MB. At 16 MB the full set on a 512 MB disk no longer
  panics in mkfs (the swap slice is added first since r6e) but panics later, in the swapper (`hat_swapout`) during
  the largest package (pubfull16-512). 16 MB was tested only with the minimal set on a 100 MB disk, which is not
  published; the standard set at 16 MB is not tested.
- **Largest tested root: a 1000 MB disk** (959 MiB root, at 64 MB; pubfull64-1000). On r6d that disk panicked after
  `mkfs_ufs`, before the swap slice was added ahead of mkfs.
- **The full set needs 512 MB or more, on ufs.** s5 cannot hold it (14-character names collide). The card's
  `cd-target.hdf` (200 MB) is too small for it.
- **Stay below 1024 MiB.** A 1024 MiB disk failed in `mkfs_ufs` (ENXIO, run `20260908-190054-cd-full-1g`).
  With the configs' hardfile geometry (16 KiB per cylinder) 1024 MiB is exactly 65,536 cylinders; the cause is not
  diagnosed. The largest empty disk in 1.0 is 1000 MB.
- **The boot slice must end below 4 GiB.** boot2 reads the kernel with a 32-bit `io_Offset` (CMD_READ), so
  UNIX_Boot past the 4 GiB mark cannot be read. The installer puts it at the end of the disk, which keeps it there on
  every disk 1.0 supports.
- **A K1 install source changes when it is used.** The installer boots the source disk's own root read-write, so
  each install rewrites cylinder-group headers, access times and a few files on it (2026-10-10: 2,517
  blocks in the first 75 MB). The card's hashes describe the disks as shipped; after a boot, a mismatch on a source
  disk is expected and is not an integrity failure. Read-only mounting is on the 1.1 list.
- **The full-set discs' metal rows are the 060 discs on the A4000D** (F2, F3); the classic full disc is tested in
  emulation only, like the rest of the classic kit.
- **The `a4092cd-*-emu` disc runs only its bench profiles.** It carries the whole `profiles/` directory for reference,
  but no `/install/monsw` or `/install/x11kit`: a reference profile with `MONSW` set or `X11KIT=rtg` stops there.
- **Netnews:** the standard and full sets install the stock `public` package; its news software makes the first-boot
  dialog ask "Do you wish to configure Netnews ...? [n]". Answer n unless you run news.
- **Boot priority:** Kickstart boots the highest-priority bootable partition. An Amix disk installed behind the A4092
  carries priority 2, the CD installer's boot disk 1: while that disk is on the bus it boots instead of the CD-to-SD
  installer (K1 preset 4). Remove it, or choose in the early-startup menu (not tested).
- **Z3660: power-cycle after a core0 abort.** If the firmware restarts itself during a run, power the A4000 off and
  on, then start again; a reset is not enough. The first r6e M4 attempt on the A4000D lost a piece of its miniroot
  after one.
- The limits in the release notes still apply: no software reboot on a real 68060, `apkg upgrade apkg` rather than
  `pkgadd`, no crash dump, interactive-only CD install, the classic kit tested in emulation only.
