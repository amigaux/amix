# M-LD4 — the loader's writes, read back on the next boot (bench half, 2026-10-26)

- **Measurement:** M-LD4 (writes through the strap's IOStdReq on each boot ROM: boot2's control-block write for try-once and one-shot, boot1's tally-block write for a loader trial, with read-back on the next boot)
- **Class:** bench, on the project's emulator rig: each row a lifecycle cell of two boots on one copy of the image, with serial capture. The Z3660 boot ROM half and both boxes are metal (S1-26).
- **Inputs:** `tests/bench/ld-rows.sh` (vehicles W1–W3 from the proven S1-19 vehicles, and each row's expected outcome from `axsim`); boot2 of 26 788 bytes (the L11 fix, before the table-driven inflate)
- **Evidence:** the workspace's `tmp/2026-10-26-s1-measure/m-ld4/run1/` (rows N27–N30c: `08-post.txt`, `08-lsstore.txt`, `06-serial.log`, the frames), rig run 20261025-205251

## 1. Rows

| Row | Store | Expected |
|---|---|---|
| W1 try-once | gen 1 good (default), gen 2 trial | boot 1: attempt recorded, gen 2 boots; boot 2: `L8 … (generation 2)`, gen 2 marked bad, gen 1 boots |
| W2 one-shot | gens 1 and 2 good, default 2, request gen 1 | boot 1: request cleared, gen 1 boots; boot 2: gen 2 boots |
| W3 loader trial | primary boot2 on trial, the same boot2 as the secondary | boot 1: boot1 records the start, `boot1 choice 0`; boot 2: `boot1 choice 201`, `B4 new loader already started once, previous loader used` |

Each row checks:
- the serial lines of both boots against `axsim`'s, in order;
- `lsstore` of the slot image after the cell against the expected store:
  control-block sequence, states and attempts, the one-shot request, the
  tally.

12 of 12. On every row the store read back after the cell matches and
both boots' serial lines match. For example, on N30 (68060) boot 2 prints

and then boots generation 1. The W3 rows show the tally with one start.

## 3. Verdict

**The bench half of M-LD4 is closed.** On the A3000 WD, Gayle and A4091
boot ROMs:
- boot2's control-block write (try-once attempt, failed-trial verdict,
  one-shot consumed) reaches the medium through the strap's IOStdReq, and
  the next boot reads it back;
- so does boot1's tally write (loader trial).

Still open, metal (S1-26): the Z3660 boot ROM, which S1-28 may need to
change if it refuses CMD_WRITE, and both boxes.
