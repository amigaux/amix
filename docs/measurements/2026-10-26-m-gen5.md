# M-GEN5 — upgrade, mark-good, rollback, one-shot, try-once (bench, both lines, 2026-10-26)

- **Measurement:** M-GEN5 (90 §2): upgrade, commit, mark-good, rollback,
  one-shot previous, and the try-once fallback on a trial that cannot
  reach multi-user. Row S2-41 (`docs/plan/stage-2.md`).
- **Class:** bench, on the project's emulator rig: one lifecycle cell of
  seven boots on one slot. Metal: one row per box per line (S2-47).
- **Inputs:**
  - the kinfo row's vehicle: the Z3660 with autoboot, KD060-Z, generation
    1 good, a 4 MiB store;
  - the box kbootset and the stand-in kernel package made from the same
    KD060-Z kernel (`tests/bench/s2-standin.sh`);
  - for the bad trial, KD060-A, whose root controller is the A4091, which
    the vehicle does not have, committed with `commit --spec`;
  - the recipe `tests/bench/README.md` "S2-41", with `mark-bad 2` on
    boot 5 (the 4 MiB store holds two raw k46 generations).
- **Evidence:** the workspace's `tmp/2026-10-26-s2/s2-41b/N36/`

## 1. Results

The rig runs `kbootset mark-good` after each login, standing in for the end
of run level 2. Its "nothing to mark" lines are left out below.

| Boot | Commands | Seen |

| 2 | (mark-good) | `amix-boot: generation 2, kernel unix 1998273 bytes`; "generation 2 is good and the default" |
| 3 | `kbootset rollback` | boots generation 2; "the default is generation 1 (was 2)" |
| 4 | `kbootset next previous` | boots generation 1; "the next boot only is changed" |

| 7 | `kbootset status` | generation 1 boots; control sequence 11, default 1, no trial; generation 1 good, generation 3 bad with 1 attempt; generation 2 gone |

After the cell, lsstore of the slot image: `ok`, generation 1 good and

Boot 7's status warned that a generation the size of the default does not
fit (198 656 bytes free). That is the 4 MiB vehicle store: generation 3
stays until a collect. The 64 MiB store of the 1.1 layout does not meet it
(40 §2.1).

## 2. One difference from the recipe: the panic reboots by itself

The recipe expected boot 6 to stop at the panic, and the L8 line on
boot 7. On the machine, the kernel reboots after its panic, so the try-once
fallback happens inside boot 6:
1. the trial's kernel panics;
2. the machine resets;
3. the loader finds the trial attempted and not good, marks it bad (L8),
   and boots generation 1.

The end state is the one expected. The recipe now says so.

The rig's own verdict for the cell is FAIL, with `b6:no-login-prompt`. Its
boot-6 watch waited 160 s for a login, because the panic and the second
loader run come first. The login and boot 6's batch did follow. The row
is judged on its expected lines, not on the rig's boot wait.

## 3. Verdict

**M-GEN5 passes on the bench for the k46 line.** Every step of the
lifecycle behaved as 40 §3 and 10 §7 specify:
- upgrade and commit;
- mark-good;
- rollback;
- the one-shot `next previous`;
- mark-bad;
- a gate-less trial committed with `--spec`;
- the try-once fallback to the good default.

The k30 line is §4. Metal: S2-47.

## 4. The k30 line (row N43)

- **Vehicle:** the installer's v7 l11-k30 disk, rig row N19's shape (A3000,
  the disk as WD unit 6), a 64 MiB store. Generation 1 is pristine:
  `kernel-k30-u` -1, K030-U with `kinfo`, build 68030-261026-01, 1 270 676
  bytes, sha256 `dfa6a1d1…`.
- **Base system:** the rc2 hook (`kbootset mark-good` at the end of run
  level 2, C2-4 §9) and the `retry` line in `bcheckrc`. So no boot needed
  a hand-run `mark-good`.
- **The bad trial:** the recipe's unit-5 `bad.spec`, which is the same
  `/stand/k30/unix` (`bss=344916`) with its root on SCSI unit 5, where
  the vehicle has no disk.
- **Evidence:** the workspace's `tmp/2026-10-26-s2-k30/s2-41u5/N43/`

| Boot | Commands | Seen |
|---|---|---|
| 1 | `kbootset build; kbootset commit` | `booted: generation 1 … kernel 68030-261026-01`; "generation 2 built", steps 1, 2, 4, 5, 7, "generation 2 committed" |
| 2 | (the hook) | `amix-boot: generation 2, kernel unix 1270676 bytes`; status: generation 2 good and the default |
| 3 | `kbootset rollback` | boots 2; "the default is generation 1 (was 2)" |
| 4 | `kbootset next previous` | boots 1; "the next boot only is changed" |
| 5 | `kbootset mark-bad 2; kbootset commit --spec bad.spec` | boots 2, the one-shot; "marked bad and collected"; "generation 3 committed" |
| 6 | — | `amix-boot: generation 3, kernel unix 1270676 bytes`. On the screen: `mountroot VOP_OPEN error 5`, `PANIC: vfs_mountroot: cannot mount root: errno 30`. The kernel reboots by itself; in the same rig boot: `amix-boot: L8 trial generation did not reach multi-user (generation 3)`, then generation 1 to login |
| 7 | `kbootset status` | generation 1 boots; control sequence 12, default 1, no trial; generation 1 pristine, generation 3 bad with 1 attempt, no generation 2 |

After the cell:
- lsstore of the slot image: `ok`, sequence 12, generations 1 and 3,
  both kernels' CRC-32 ok;
- the rig's C2-5 check: the booted kernel's SHA-256 equals generation
  1's manifest (`store-booted: OK`).

**The errno differs from k46's (89) for the same failure.** errno 30 is
`EROFS` and 89 is `ENOSYS`. The stock `vfs_mountroot` tries every
filesystem row and reports the last row's errno (30 §3): k30 has 13 rows,
k46 12. The failure itself is the line before:
- here, `VOP_OPEN error 5` (`EIO`, no disk at the unit);
- on k46, error 6 (`ENXIO`, the A4091 trial's absent controller).

The errno is not part of any expected line.

**The rig's verdict** for the cell is FAIL with `b6:no-login-prompt`. That
is its boot-wait timing, not a row result: the panic stayed on the screen
for more than 150 s before the kernel's own reboot, and the login came
after the second loader run, as on k46 (§2).

**An earlier run (N43, the first)** used K030-IDE as the bad trial. That
family still drives the A3000's controller and mounted root. Its
fallback came from `mark-good` refusing on a kernel without `kinfo`, a
valid try-once path but not a mountroot failure, so it is not the row of
record. The recipe now uses the unit-5 spec on both lines.

**Verdict for k30: M-GEN5 passes on the bench.** With §3, M-GEN5 is
closed on the bench on both lines.
