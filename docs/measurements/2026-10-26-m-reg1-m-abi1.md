# M-REG1, U5, M-ABI1, M-ABI2 and M-MOD1 — the module core's facts in today's kernels (2026-10-26)

- **Measurements** (90 §3, stage 3; plan item S3-40):
  - M-REG1: the registry values against the built kernels;
  - U5: can the switch tables be moved;
  - M-ABI1: one k46 ABI or two;
  - M-ABI2: the symbol block through `elf2brel`;
  - M-MOD1: the root-class modules' sizes, and so the arena's capacity.
- **Class:** bench (host computation), read-only over existing build
  outputs.
- **Tools:** `tools/measure/m-reg1.py`, `m-abi1.py`, `m-mod1.py`
  `<workspace>`. Raw output in this repository's `build/s3-40/`, not
  tracked.
- **Inputs, read-only:**
  - the kernels of record, `amix-kerntools/work/k0-chains/<family>`: the
    `ET_REL` k46 kernels, and the k30 kernels' `.etrel` before `elf2brel`;
  - the driver objects in `amix-040-060-port/build/` and
    `amix-kerntools/work/cross-kernel-*/usr/sys/`;
  - cdfs from `amix-cdfs/build/amix-kernel/`.

Ten kernels: K030-U, K030-IDE, K030-A4091-IDE, K030-U-FD, KD040-A,
KD060-A, KD060-Z, KD060-ZA, KD060-FD and K060.

## 1. M-REG1 — the registry against the kernels

| Fact | All ten kernels | Registry (20 §6) |
|---|---|---|
| `sysentsize` | 142 | the core arms only at 142 |
| `sysent[64..69]` | all `nosys` | syscalls 64–69 for the core: free |
| `cdevsw` | 70 rows of 52 bytes; empty rows 7, 38–39, 42–45, 47–48, 51, 53–69; 49 and 52 empty too except where a static driver holds them | as 20 §6 |
| major 49 | empty, except KD060-Z, KD060-ZA and K060, where the static `zz9000` holds it | z3660rtg |
| major 51 | empty in the image everywhere, but **filled at boot** in KD060-Z, KD060-ZA, KD060-FD and K060: their z3660eth init (`parinit`, or its renamed form after a wrapping pass) stores `cdevsw[51].d_str` at run time; free in the 030 kernels and the A families (corrected 2026-10-26; the first run read the image only) | z3660eth |
| major 52 | empty, except KD060-Z and KD060-ZA (the static `monsw`) | monsw |
| major 53 | empty everywhere (`kinfo` comes with S2-10/S2-11) | kinfo, *proposed*: confirmed free |
| `bdevsw` | 32 rows of 32 bytes (seven entry points, `d_flag`); empty 0–15, 21–31 | block majors free 0–15, 21–31: confirmed |
| `fmodcnt` | 11 | the core's 11 stock rows: confirmed, so patch 12 never truncates |
| `nexectype` | 3 | upstream copies 3 rows |
| `nfstype` | 13 on k30, 12 on k46 | as 30 §6 |
| `int2_tbl` | k30: 6 handlers (`aciaaintr jbintr a2091intr a3091intr aenintr ideintr`); k46: 5 (`… a3091intr_demux aenintr` on the A families and Z, `a3091intr` on K060) | the chain walker takes the last handler slot (30 §4) |

**Verdict:** every registry value 20 §6 marks proposed or assumed holds
in the kernels of record. The majors the module forms take become free
once the static drivers leave the module kernels (S3-20):
- 49, 51 and 52 on KD060-Z and KD060-ZA;
- 49 and 51 on K060;
- 51 on KD060-FD.

**Correction (2026-10-26).** The first run read only the rows as they
stand in the image, so it called major 51 free on kernels whose
z3660eth fills the row at boot. The port's dry run of S3-20 found it.
`tools/measure/m-reg1.py` now also counts a store relocated against
`cdevsw` inside a registry row, and names the function it is in.

## 2. U5 — the tables can be moved

For `execsw`, `fmodsw`, `vfssw`, `cdevsw` and `bdevsw`, every reference in
every kernel is a relocation against the table's own symbol, all from
`.text`:

| Table | References |
|---|---|
| `execsw` | 4 |
| `fmodsw` | 13 |
| `vfssw` | 29 (KD060-FD: 30) |
| `cdevsw` | 44 or 45 |
| `bdevsw` | 21 |

No reference reaches a table through its section symbol plus an offset,
which moving the table would miss. **U5 holds:** the core can grow a
table into `.data` by retargeting the relocations against its symbol
(30 §6).

## 3. M-ABI1 — one k46 ABI

KD040-A and KD060-A are the same image except for **one byte**, the CPU
stamp (`cmp -l`: 1 difference). Their 4 458 defined globals agree in name,
kind and data-object size. **One k46 family serves the 68040 and the
68060.** That answers OQ-20.2 for the kernels of record. If the port ever
builds the two from different sources, the fingerprint (C3-3 §4) catches
it.

**The DDI v1 names today** (C3-2 §3; `+` defined in all ten kernels unless
noted):
- **Defined everywhere:**
  - console, errors and panic state: `printf`, `cmn_err`, `panic`,
    `panicstr`;
  - memory: `kmem_*`, `sptalloc`/`sptfree`, `vtop`;
  - copy and string helpers;
  - `sleep`, `wakeup`, `timeout`, `untimeout`, `lbolt`;
  - `suser`, `drv_priv`, `getmajor`, `getminor`, `makedevice`;
  - `autocon`, `bprobe`;
  - every STREAMS name of the list;
  - `bootinfo`.
- **Missing everywhere, so the core provides them:**
  - `dma_alloc`, `dma_free`;
  - `spl0`…`spl7`, `splx` as functions (the kernels inline them);
  - `intr_attach`, `intr_detach`, `if_attach`, `if_detach`,
    `cons_hook_set`, `cons_hook_clear`;
  - on k46, `dma_prepare` and `dma_complete`.
- **Missing on one line:**
  - `__udivdi3`, `__umoddi3`, `__lshrdi3`: on k46 (k30 has them);
  - `cputype`: on k30 (k46 has it);
  - `dev_kvmap`/`dev_kvunmap`: on KD060-Z and K060 (the A families have
    them from the A4091 pass).

The post-link gate (C3-2 §2) catches any of these left unprovided.

## 4. M-ABI2 — the symbol block through `elf2brel`

`elf2brel` (amix-kerntools `tools/elf2brel.py`) was run on K030-U's
`.etrel` under `build/s3-40/`:
- the output is byte-identical to the shipped brel;
- it folds every relocation one to one, with no limit: `.rela.text`
  25 575, `.rela.rodata` 65 and `.rela.data` 3 899 in, 29 539 pairs out.

The symbol block (C3-2 §1) adds one `R_68K_32` per exported name plus two
for the header. The stage-3 allowlist is about 90 names; the core tier
adds about 115 in stage 5. That is about 200 relocations, 1 600 bytes of
pairs: a 5 % rise in `.data`'s relocations. Even upstream's full table
(about 1 000) would cost only 8 000 bytes. **M-ABI2 holds** for the
format. The real block is checked by the post-link gate when S3-21 links
it.

## 5. M-MOD1 — the root set and the arena

Allocated bytes (PROGBITS, NOBITS and COMMON) of today's objects:

| Module | k30 | k46 | Stands in for it |
|---|---|---|---|
| z3660scsi | 2 517 | 5 013 | — |
| a4091 | 5 064 | 6 156 | — (on the stock SCSI layer `scsi.o`, which stays in the floor) |
| gayle-ide | 10 792 | 11 740 | — |
| a4000t-710 | 5 064 | 5 564 | the A4091 driver (the same 53C710); none exists yet |
| ufs | 55 980 | 55 980 | k46: the k30 object, until M-FS1 carves the k46 one |
| s5 | 39 228 | 39 228 | as ufs |
| cdfs | 69 080 | 69 120 | — |
| ramdisk | 524 | 524 | the stock `ram` driver; ours is not written |

Each line's set comes to about 191 KB (k30) and 196 KB (k46). That
includes 16-byte alignment, the `AXA1` directory and a 2 KiB manifest
copy (C3-4).

**Arena capacity = 2 × the set rounded up to 64 KiB = 0x60000
(384 KiB) on both lines.** S3-20 and S3-21 reserve it, and C3-3's `AXK1`
and the sidecar's `arena=` carry it.

**Consequence.** The arena is a zero block in `.data`, so a module
kernel's file is 384 KiB larger, raw:
- a 64 MiB store holds about four fewer generations at that size (M-GEN1:
  32 → about 28 ET_REL k46), still far above the five a commit needs;
- deflated media lose almost nothing (zeros compress to a few hundred
  bytes);
- a 1.0-sized boot slice gets tighter, and 1.0 boxes reinstall to the
  1.1 layout anyway (D-3 §5).
