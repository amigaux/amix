# M-NET1a/b — netinstall miniroot size (2026-10-25)

- **Measurements:** M-NET1a (uncompressed netinstall miniroot per line), M-NET1b (its deflate-compressed size); the S0 freeze condition (`docs/spec/00-overview.md` §5)
- **Class:** bench (host computation over the real build outputs); nothing was built
- **Tool:** `tools/measure/m-net1.py <workspace> <netdir>` (this repository); raw JSON output reproduced in §4
- **Budget of record:** 890 880 B per DD volume (P-28 D37), so 1 781 760 B for a floppy pair

Paths below are relative to the Amix project workspace.

Compression: the file set is written as one ustar archive in path order and
deflate-compressed (zlib level 9). A filesystem image of the same files adds
block padding and metadata; padding is zeros and compresses to almost
nothing, so the archive is a close lower bound for a compressed image.

**Finding on the way.** The stock network binaries are dynamically linked:
every one names `/usr/lib/libc.so.1` as its interpreter and needed library,
and all but `slink` also need `libsocket.so` and `libnsl.so` (`readelf -l -d`
on the extracted files). `libc.so.1` (206 876 B) is itself the runtime
linker on this system and needs nothing else, so `ld.so.1` is not required.
The earlier ~0.5 MB estimate (`tmp/2026-10-22-modules-proposal/medium-network.md:59-66`)
left out `libc.so.1`; it is already on both 1.0 root floppies, so it costs
nothing extra here.

## 2. Left out (cannot be counted without building)

| Item | Why | Effect |
|---|---|---|
| `kbootset` (static) | not written yet (M-GEN4) | comes out of the margin below |
| The 1.1 floor kernel + root-class modules | not built yet (M-NET1c, deviation DV-1) | the 1.0 floppy kernels stand in: they carry their root controllers and filesystems statically, so kernel + modules should be of the same order |
| The 1.1 store overhead per volume | the floppy store layout is not frozen (M-NET1d, DV-1) | the budget of record already excludes the 1.0 10 KiB prefix; any larger 1.1 prefix comes out of the margin |
| Changes to the installer for netinstall (network setup dialog, the HTTP install path) | not written yet | comes out of the margin |
| Public key, device nodes | negligible (bytes) | — |
| Optional `usr/bin/ftp` (63 776 B) and an NFS mount helper | not required by D-3 §2 | adds about 24 KB compressed if wanted |

The network binaries are the stock 2.1 tape versions; patch-level versions
may differ slightly in size.

## 4. Verdict

- **Form A with the 1.0 installer engine as composed today does not meet
  the rule** on either line: k30 fits by only 1.1 % (below the 5 % margin of
  `docs/spec/50-media.md` §5.1) and k46 is over by 2.0 %, before `kbootset`,
  the 1.1 store overhead and the netinstall installer changes.
- **Form A with the trimmed installer engine fits** with 16.1 % (k30) and
  13.0 % (k46) margin.
  The margin must absorb `kbootset`, the store overhead and the installer's
  network additions (all listed in §2), and the trim assumes the static
  `pkgadd` needs no `pkginfo` at run time — to be confirmed when the
  netinstall miniroot first runs (M-NET1f).
- **Decision:** form A (floppy pair, trimmed engine) is the target; form B
  (small disk image + CD image) remains the fallback if M-NET1c, M-NET1d or
  `kbootset` take the margin below 5 %. OQ-50.2 is narrowed to that check.
