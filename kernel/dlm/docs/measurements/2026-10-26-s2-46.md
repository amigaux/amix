# S2-46 — the exit row: a box upgraded and rolled back with apkg alone (bench, both lines, 2026-10-26)

- **Row:** S2-46 (`docs/plan/stage-2.md`). It is stage 2's exit gate on the
  bench (80 §2): "a box upgraded and rolled back with apkg alone".
- **Class:** bench, on the project's emulator rig, four boots of one slot.
  Metal: S2-47.
- **Inputs:**
  - the vehicle of the kinfo row: the Z3660 with autoboot, KD060-Z,
    generation 1 good (the pristine generation), a 4 MiB store, no
    `/etc/default/bootset` (auto);
  - amix-packages' S2-12 set, from a file catalog with the kernel-space
    block: `kbootset` 1.1.0.261025-4 (from d64bad7, binary
    `9cf75c1c…`), `kernel-k46-z` -2 (`kern46z`, a brel kernel with `bss=`
    in its sidecar), `loader-amix` -2 (`ldramix`);
  - apkg 0.3 from amix-packagemanager;
  - the recipe `tests/bench/README.md` "S2-46".
- **Evidence:** the workspace's `tmp/2026-10-26-s2/s2-46v2/N36/`; the first
  run's in `tmp/2026-10-26-s2/s2-46/N36/`.

## 1. First run: the journal could not be written

On the first run, boot 1 installed the three packages and the trigger
built generation 2. The commit stopped at its first step:

```
kbootset: step 1 journal
kbootset: cannot write the journal
apkg: kbootset commit failed: an I/O error, a read-back mismatch or a damaged boot store (status 1)
apkg: the generation was built but not committed: the next boot is unchanged
```

apkg exited with status 6. The next boot was generation 1, unchanged, as
C2-4 promises for an error before the commit point.

**Cause:** apkg names the journal (`--journal <target>/var/kbootset/journal`).
kbootset made `/var/kbootset` only for the default path, when no
`--journal` was given, and the box had no such directory.

**Change** (d64bad7, C2-4 §2 wording in 0033922, no version bump): kbootset
makes the missing directories above the journal (mode 0755) whenever it
writes it, named or default. `tests/host/kbox.sh` commits with apkg's
named journal after removing the directory. Belt and braces, the
`kbootset` package also ships `/var/kbootset`.

Boot 4's status also warned that a generation the size of the default no

Generation 2's `created` time is the box clock's, which the emulator does
not set (a 1978 date). The field is informational; nothing orders by it.

## 3. Verdict

**S2-46 passes on the bench.**
- The upgrade was apkg's alone: no file of the upgrade was placed by
  hand. The row's prerequisites, laid down before the upgrade, were apkg
  itself, its catalog source and the `retry` line in `bcheckrc`.
- `kbootset check` reported 0 problems after boot 2.
- The rollback brought generation 1 back.

With M-GEN3 (`2026-10-26-m-gen3.md`), stage 2's exit gate (80 §2) is met
on the bench for the k46 line. The k30 line is §4. The metal rows are
S2-47.

## 4. The k30 line (row N45, the installer's v10 disk)

- **Vehicle:** the installer's v10 l11-k30 disk (`8efc7b60…`), rig row
  N19's shape (A3000, the disk as WD unit 6), a 64 MiB store. The
  installer (amix-installng 814139e) installs `kbootset`, `loader-amix`
  and the kernel as apkg packages in one transaction, with one pristine
  generation:
  - generation 1 is `kernel-k30-u` -1, K030-U with `kinfo`,
    68030-261026-01, 1 270 676 bytes, sha256 `dfa6a1d1…`;

  `kernel-k30-u` -2 (the same bytes, a higher revision), `loader-amix`
