## 2. M-FL1 — the floor kernel

| | k30: -17 (stage 4) | k30: -18 (cut) | k46: -67 (control) | k46: -66 (cut) |
|---|---|---|---|---|
| file | 1 637 928 | **1 534 496** | 2 448 222 | **2 411 588** |
| text / data / bss | brel (one section), `bss=352196` | brel, `bss=346388` | 1 100 244 / 533 488 / 71 872 | 1 100 244 / 533 488 / 71 872 |
| of which the arena (zeros) | 393 216 | 393 216 | 393 216 | 393 216 |
| `rootfs=` in the sidecar | `ufs,s5` | none | `ufs,s5` | none |

**k30:**
- The cut saves **103 432 bytes of file** and **5 808 of bss**, so
  **109 240 bytes of memory** against -17.
- The carved objects account for 96 597 of that, their allocated size
  in §1. Most of the rest is the brel's relocation records for those
  objects, plus the two `vfssw` rows and `inoinit`.
- -17 and -18 also differ by the core revision, and S5-10 built no
  same-revision control, so the split is approximate. The total is
  exact.
- The memory comes back only on a box that loads the module: a
  generation loads ufs, and s5 only when it mounts one.

**k46:**
- The cut's file is **36 634 bytes smaller** than its control: the 380
  symbols and the relocations of the carved code are gone.
- The sections are the same size, because the 89 396 bytes of dead
  `.text` and `.data` stay zeroed in place: no address moves, which was
  the agreed option (b).
- In memory the cut saves only the 5 768 bytes of private COMMONs that
  the loader no longer places. The ufs module then adds its 56 636 bytes
  on every generation, since a k46 box roots on ufs.
- A relink that drops the zeros is not in stage 5.

## 3. M-MOD1 with ufs promoted

The root filesystem's module is promoted to root class and goes into the
arena:
- ufs takes its file, 16-aligned (78 592), plus its `bss=` (NOBITS and
  COMMON, 4 744): **83 336 bytes**;
- s5, on a k30 s5 root, takes 58 320 + 1 076 = **59 396**.

| Generation | arena need | of 393 216 |
|---|---|---|
| stage 4's of record (four controllers, the manifest copy) | 53 996 | 14 % |
| the same with ufs promoted (every disk root from S5-12 on) | about 137 400 | 35 % |
| the largest: every controller plus cdfs promoted (a CD root) | about 155 000 | 40 % |

Only one filesystem is promoted per generation (C4-6 §1), so the CD root
stays the largest set. Twice it, about 310 KB, is under the 384 KiB the
arena keeps on both lines.
