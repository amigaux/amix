# M-GEN3 — a power cut at each commit step (bench, 2026-10-26)

- **Measurement:** M-GEN3 (a power cut at each step of `kbootset commit` leaves a booting generation; the journal is cleaned up on the next run). It is stage 2's exit condition (80 §2: "every power-cut point leaves a booting generation").
- **Class:** bench, on the project's emulator rig. The rig's cut at a console marker (S2-40) SIGKILLs the emulator, then a second boot runs on the same slot copy. Metal: one row per box (S2-47).
- **Inputs:**
  - the kinfo kernel's vehicle: N23's shape, the Z3660 with autoboot, KD060-Z, generation 1 good, a 4 MiB store;
  - the box kbootset;
  - the stand-in kernel package (`tests/bench/s2-standin.sh`);
  - the rows of `tests/bench/README.md` "S2-42": `KBOOTSET_HOLD=N`, the commit held in the foreground of its own session.
- **Evidence:** the workspace's `tmp/2026-10-26-s2/s2-42c-N{1,2,4,5,7}/N36/`

## 1. Results

| N | Cut before | Boot 2 boots | Boot 2's `kbootset status` | lsstore after the cell |
|---|---|---|---|---|
| 1 | the journal | generation 1 | no journal message | ok; generation 1 only |
| 2 | the members | generation 1 | "the commit of generation 2 was interrupted before its commit point; nothing of it remains" | ok; generation 1 only |
| 4 | the manifest | generation 1 | as N = 2 | ok; generation 1 only |
| 5 | the control block | generation 1 | as N = 2 | ok; generation 1 only |
| 7 | clearing the journal | generation 2 first; then, after a restart, `L8 trial generation did not reach multi-user (generation 2)` and generation 1 | "the commit of generation 2 had completed when it was interrupted"; generation 2 bad, 1 attempt | ok; generation 1 good, generation 2 bad |

Every row booted, and every store read back consistent. For N = 1, 2, 4
and 5 the result is exactly as expected. On each, kbootset made
`/dev/kinfo` once, because the image had none.

## 2. Finding: the fsck-repair reboot spent the trial's attempt

On every row, the first boot after the cut ran the loader **twice** before
multi-user; rows without a cut run it once. The cause is in the stock
`/sbin/bcheckrc`. When the root filesystem is not clean, it runs `fsck -y`
on it and then reboots (`uadmin 1 1`), even after a successful repair
(`case 0|40: *** REBOOTING SYSTEM ***`).

On N = 1–5 that costs nothing but time. On N = 7 the commit had completed,
so the first boot was the trial's: the loader wrote its attempt (10 §7.2),
fsck repaired the root and rebooted, and on the second run the loader
found the trial attempted but not marked good. It marked it bad (L8) and
fell back. **A generation committed just before a power cut could never
get its trial boot.** The same holds for any trial boot that meets an
unclean root.

## 3. The change

`kbootset retry` (40 §3.3, 10 §7.2, C2-4 §7):
- The base system's `bcheckrc` calls it just before each reboot that
  follows a root repair.
- When kinfo says the booted generation is the trial on its attempt, the
  attempt is given back, at most twice per trial. A root that never stays
  clean still ends in the try-once fallback.
- It writes the boot store's control block only: no journal, no
  `/etc/default/bootset`, no `/dev/kinfo`. The root may be read-only or
  unrepaired.
- Host-tested:
  - `t_kbootset`, with the loader's own attempt write between the
    retries: two refunds, the third stands, then L8;
  - `kbox.sh`: retry from the box form with a read-only root, then the
    next loader run boots the trial again.

## 4. Verdict

**M-GEN3, bench: every power-cut point leaves a booting generation**, the
exit condition, met on all five rows.

**N = 7 again, with the change** (`tmp/2026-10-26-s2/s2-42r-N7/N36/`):
the slot's `/sbin/bcheckrc` carries the `retry` line (C2-4 §7), with the
box kbootset `f4a6632b…`. Boot 2:
1. Loader run 1 boots generation 2, the trial.
2. The frames show "The root file system (/dev/rdsk/c6d0s1) is being
   checked", fsck phases 1–2, and the reboot. The retry line and "***
   REBOOTING SYSTEM ***" fall between frames.
3. Loader run 2 boots generation 2 again, with no L8: the attempt came
   back.
4. "The system is ready", login, and status: "the commit of generation 2
   had completed when it was interrupted".
5. mark-good: "generation 2 is good and the default".
6. After the cell: control sequence 6, default 2, lsstore generation 2
   good.

**M-GEN3 is closed on the bench.** A power cut at every commit step
leaves a booting generation, and a generation committed just before a cut
still gets its trial boot. The base system's `bcheckrc` must carry the
`retry` line (amix-installng). Metal: one row per box (S2-47).

## 5. The k30 line: N = 7 (row N44)

- **Vehicle:** the installer's v7 l11-k30 disk (as M-GEN5 §4): A3000 WD
  unit 6, a 64 MiB store, generation 1 pristine (`kernel-k30-u` -1), the
  rc2 hook and the `retry` line.
- **The commit:** of generation 2, composed from the installed package
  and held before step 7 (`KBOOTSET_HOLD=7`), then cut.
- **Evidence:** the workspace's `tmp/rig-run-20261026-023919/N44/`, rig
  verdict PASS.

Boot 1 printed "generation 2 built", the step markers 1, 2, 4, 5, 7 and
`holding before step 7`, then the rig cut the power. Boot 2:
1. Loader run 1 boots generation 2, the trial (`kernel unix 1270676
   bytes`).
2. The root fsck repairs and reboots. `retry` gives the attempt back.
3. Loader run 2 boots generation 2 again, with no L8.
4. The rc2 hook's `mark-good` marks it good. The row's `status`:
   control sequence 7, default 2, generation 2 good, `booted: generation
   2 … 68030-261026-01`.

The hook is now the first kbootset run of the boot. It reported the
journal ("had completed") on the console and cleared it, so the row's
own `status` shows no journal message.

**k30 passes:** a generation committed just before a cut gets its trial
boot, through the fsck reboot, on the 030 line too.
