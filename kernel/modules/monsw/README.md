# monsw — the monitor switch

`monsw` owns one machine resource: the CIA-B line(s) that flip a monitor or KVM between the
Amiga's native video and an RTG card. It is card-independent. A card driver (z3660rtg) calls
its kernel API, and user programs use `/dev/monsw` (character major 52, minor 0).

It is a loadable kernel module for both Amix kernel lines, `k30` (68030) and `k46`
(68040/68060), built with amix-dlm's ABI kit. The same source still builds the static object
that the 68040/68060 port links into its static kernels (see "The static form").

## The configuration value

The value is a sum of four bits. They have the same meanings as the Z3660 firmware's
`monitor_switch` setting, so a box behaves alike under AmigaOS P96 and Amix:

| Bit | Name | Meaning |
|---|---|---|
| 1 | `MONSW_CTS` | drive CIA-B PRA bit 4 (CTS; PRA at 0xbfd000, mask 0x10) |
| 2 | `MONSW_SEL` | drive CIA-B PRA bit 2 (SEL, mask 0x04) |
| 16 | `MONSW_CTSLVL` | invert CTS: RTG is the bit clear (without it, RTG is the bit set) |
| 32 | `MONSW_SELLVL` | invert SEL, likewise |

- 0 means "never touch a line".
- The valid values are -1 (unset), 0–3, 16–19, 32–35 and 48–51. For example, 34 = drive
  SEL, with RTG = SEL low.
- Any other value is reported once on the console (`monsw: value 0x.. is not a 1/2/16/32
  bit sum; taken as 0`) and taken as 0.

**Where the value in effect comes from.** The first source that is set wins:
1. **forced**: the module parameter `config` (`monsw_config` in the static kernel) at 0 or
   above. A forced value that is not a valid sum is still forced, and is taken as 0. While a
   value is forced, `MONSWIOC_SETCFG` answers `EBUSY`. At load the console says
   `monsw: switch value N (patched)`.
2. **SETCFG**: root's last `MONSWIOC_SETCFG`, typically from `/etc/monsw`, applied by an rc
   step at boot. -1 clears it.
3. **seed**: the value the first card driver offered when it registered (the Z3660 reports
   its firmware setting, register 0x318). Later cards' seeds are ignored.
4. otherwise 0.

**How the lines are driven.**
- Only the enabled bits are touched, at IPL 4. The same port also carries the serial RTS/DTR
  and the parallel status lines.
- The level is latched in PRA before the bit becomes an output in DDRA (0xbfd200), so a line
  never shows a stale level.
- Nothing is driven until the first `monsw_set()` or `MONSWIOC_RTG`/`MONSWIOC_NATIVE`. Loading
  the module touches no line.
- If the value changes while the state is RTG, the old lines go back to native before the
  new ones take the state.

**The device.** Open `/dev/monsw` and use these ioctls:
- `MONSWIOC_RTG` and `MONSWIOC_NATIVE` switch.
- `MONSWIOC_GETCFG` fills a `struct monsw_info`: the value, its source, the state, the
  holder flag and the number of cards.
- `MONSWIOC_SETCFG` takes the value itself as its argument. It is root-only (`drv_priv`), and
  gives `EINVAL` for anything other than -1 or a valid sum.

On the last close, the switch returns to native if its holder had asked for RTG. A holder
that dies therefore cannot leave the screen on RTG. A holder that only asked `GETCFG` leaves
the line alone.

**The kernel API** (`sys/monsw.h`, `_KERNEL`), for card drivers:

| Function | What it does |
|---|---|
| `monsw_register(name, seed)` | returns a handle, or -1 when all four slots are taken |
| `monsw_unregister(handle)` | releases the slot |
| `monsw_set(rtg)` | 1 = RTG, 0 = native; acts only on a change |
| `monsw_lastclose(handle)` | the card's device had its last close: go native, unless a `/dev/monsw` holder wants RTG |

A module that calls them names `monsw` in its `depend` key and lists this module's object in
its Makefile's `DEPS`.

## The module

| `.moddata` key | Value |
|---|---|
| `name` | `monsw` |
| `class` | `demand`: it loads at the first open of `/dev/monsw`, or before a module that names it in `depend` |
| `majors` | `c:52` (registered to `monsw` in the kit's `registry/majors`) |
| `unload` | `never` |
| `param` | `config:int:-1:-1:51` |
| `cpu`, `kabi`, `cc` | from the kit: `68030` / `k30.1.0` on k30, `68040` / `k46.1.0` on k46 |

The module's entry points:
- **`_load(params)`** reads `config` from the parameter string and runs `monswinit()`.
  - The string is `name=value` pairs separated by spaces, or 0. `config` takes C3-1's `int`
    form: decimal, with an optional `-`.
  - If `config` is absent or negative, the value is unset (-1). A value of 0 or above is
    forced, as described above.
  - A decimal that is not a valid bit sum, however long, is forced and taken as 0 (above).
  - `kbootset` only ever passes decimals. If `config` is there but is not a number, the console
    says `monsw: config '<text>' is not a number; unset` and the value stays unset: a bad
    parameter never blocks root's `MONSWIOC_SETCFG`.
- **`_unload`** is never called by `moduload`, because `unload` is `never`. The core still
  calls it if a load fails after `_load` succeeded. It returns `EBUSY` while a card driver
  holds a handle. Otherwise it returns the switch to native if it was on RTG, and unsets
  `config`.
- **`_halt`**: there is none (the wrapper's entry is 0).

The `cdevsw` row holds open, close and ioctl.

The module imports only DDI v1 names: `copyout`, `drv_priv` and `printf`, plus `mod_drvops`
for the wrapper; `monsw_conf_data` is a weak reference. Its globals are the API above plus
`monsw_config`, `monswinit`, `monswopen`, `monswclose`, `monswioctl`, `monsw_drvdata` and
`monsw_wrapper`.

**To set a box's value**, use one of these:
- a line `param config=34` in `/etc/conf/modreg.local.d/monsw`, owned by the administrator;
- the same line in an installer's `modreg.d` default;
- leave `config` unset and let `/etc/monsw` reach the driver through `MONSWIOC_SETCFG` at boot.

## Size and memory

amix-dlm's C3-1 §6 (version 4) limits a module's allocated image to 256 KiB and its file to
under 256 KiB. C3-6 §1 limits each kernel memory request a module makes to 256 KiB. monsw is
far below both. The figures are from the built objects; they are the same on both lines.

| | monsw | Limit |
|---|---|---|
| file (`mod.d/monsw`) | 5,197 bytes | under 256 KiB |
| allocated image (the size `modcheck` prints) | 2,200 bytes: `.text` 1,584, `.data` 432, `.moddata` 161, `.bss` 16; no COMMON symbols | at most 256 KiB |
| the core's working set for a load from a file (file buffer, tables, image; `modcheck`'s estimate) | about 15 KiB | `modcheck` warns above 160 KiB for a demand-class module |

monsw makes no kernel memory requests at all:
- Nothing in the source calls `kmem_alloc`, `kmem_zalloc` or `sptalloc`. The only imports are
  `copyout`, `drv_priv`, `printf` and `mod_drvops`.
- `_load` reads `config` from the parameter string where it lies. Its one buffer is 16 bytes
  on the stack, for the text of a `config` that is not a number. Then `monswinit()` works out
  the value in effect.
- All state is static, in `.data` and `.bss`: the value and its sources, the switch state,
  the holder flags and the four card slots. `struct monsw_info` for `MONSWIOC_GETCFG` is built
  on the stack and copied out.
- It maps no device window. CIA-B is reached at its fixed addresses through the kernel's
  transparent translation, so there is nothing to map in `_load` or to release in `_unload`.

## Building

You need:
- the pinned gcc-cross-amix (`m68k-cbm-sysv4-*`, GCC 2.7.2.3) on `PATH`;
- `python3`;
- the built kits of kernel/dlm (`make kit` there).

```sh
make -C monsw/module               # both lines
make -C monsw/module k46           # one line
make -C monsw/module test          # the host test (any host cc)
make -C monsw/module static        # the static object per line, with its sha256
```

`DLM` names the dlm directory (default `../dlm`, that is `kernel/dlm`), or `KIT_k30` and
`KIT_k46` name the kits directly.

The objects are `monsw/build/k30/mod.d/monsw` and `monsw/build/k46/mod.d/monsw`. The kit's
`modfix` and `modcheck.py` check each one. The build also checks that the `<sys/monsw.h>` the
compiler took is this repository's `include/sys/monsw.h`. If the kit carries another one, the
build stops and asks for the kit to be rebuilt.

## The static form

Without `MONSW_MODULE` the source is the static driver that amix-040-060-port's
`relink-040-monsw.sh` links into its kernels: a free `cdevsw` row and `monswinit()` from the
`parinit` hook. The port keeps its own copy of `src/monsw.c` until the static kernels retire.
Every change to monsw lands here first.

`module/static-port.sh` compiles both copies with the port's flags and requires the two
objects to be byte-identical. Those flags are `AMIX_KERNEL_CFLAGS` with `-m68040`, against the
port's Model-B sysroot.

## Packages (amix-dlm C3-5)

One package per line, minted by amix-packages:

| | k30 | k46 |
|---|---|---|
| catalog name | `monsw-k30` | `monsw-k46` |
| pkginst | `monsw30` | `monsw46` |
| version | `module/VERSION` | `module/VERSION` |

Each package has `CATEGORY` `system` and no scripts. It ships:
- `/etc/conf/mod.d/monsw`, the object;
- `/etc/conf/modreg.d/monsw`, comments only, because the package sets no parameter;
- `/dev/monsw` as a pkgmap device entry, `c 52 0`.

## Testing

**`test/hosttest.sh`** runs on the host, with no box. It compiles the shipped `src/monsw.c`
with `-DMONSW_MODULE` after these substitutions:
- the IPL macros become counters;
- the CIA-B addresses become test memory;
- the K&R `printf` declaration is dropped.

It then checks:
- the parameter parser;
- the forced, SETCFG, seed and unset precedence, also after a parameter that is not a number;
- the invalid-value report, given once;
- the port bits driven for 34, 17, 1 and 2;
- the native-first change in RTG state;
- the last-close rules;
- `_unload`;
- the `cdevsw` row.

**`test/monswtest.c`** is the on-box instrument, one step per run: `get`, `rtg [secs]`,
`native`, `set <value>`, `bad`. Build it with the guest's `cc -I<amix>/kernel/modules/include`, or
with the project's userland cross compiler.
