# core/ — the module core

The loadable-module core of Amiga UNIX 1.1 (docs/spec/30-module-core.md).
It is a patch queue on **kdedon's DLM core** from the ashnazag project:
six system calls, an ELF relocatable loader, a kernel symbol block, and
the character-device, STREAMS, exec and hook linkages. The core is MIT
licensed, "Copyright (c) 2026 kdedon", and its licence is
`upstream/LICENSE`. Our thanks to its author.

| Path | What |
|---|---|
| `upstream.pin` | the upstream URL and commit the queue is based on |
| `upstream/` | upstream's `kernel/dlm` at that commit, unmodified, with upstream's `LICENSE` |
| `patches/NNNN-*.patch` | our changes, one self-contained change per patch, applied with `patch -p1` from `upstream/`'s root |
| `series` | the order the patches apply in |

The tree is never edited in place. A change is a patch. When the pin
moves to a later upstream commit, patches upstream has taken are dropped
from the series. The queue's base is the MIT commit in `upstream.pin` or
a later one; the project's earlier commits are GPL-2.0 and are never
used.

`tests/core/run.sh` (`make core`) builds the core from the patched copy
with this repository's toolchains and runs upstream's own host tests
against our kernels (M-CORE1).

| 0001 | `trampoline-hold-volatile` | The exec and cdev trampolines set the hold after `setjmp` and read it on the `longjmp` path. ISO C leaves such a variable indeterminate unless it is `volatile`: GCC 2.7.2.3 kept it in memory, but GCC 15 at `-O` put it in a register, and the state harness failed three checks. | not yet (OQ-30.6) |

| 0003 | `moddata-v2-kabi-pin` | 30 §2 patch 4, contract C3-1. Wrapper revision 2, and `.moddata` version 2 (`MD2\0` plus key=value strings), every key checked. The kernel's kabi and pin come from the kernel build (`DLM_KABI`, `DLM_PIN`). `mkmod` writes version 2 (`-K`, `-P`), and `modfix` checks it (`-1` lets the harness's version-1 case through). | 0009 | `manifest-only-loading` | 30 §2 patch 17, contract C3-4. | 0010 | `marc-post` | 30 §2 patch 16 (the boot-class half), C3-5. `dlm_marc_post()` registers the demand-class majors from the manifest, then loads the boot-class records in manifest order unless `match=` names no board here (`dlm_plat_match`), with one console line each. The state harness builds `dlm_str.c` and `dlm_ddi.c` (host stand-ins for `sys/stream.h` and `sys/conf.h`) and gains boot-class driver cases and ifstats backstop cases (the link first, in the middle, last; after a failed `_load`, a forgetful `_unload` and a failed linkage). | not yet |

| 0025 | `modadmin-msgbuf-words` | `modadmin -L` prints one line of the ring's words first (`putbufsz`, `putbufwpos`, `putbufrpos`, `conslogging`, `prt_where`, read by `lseek` on `/dev/kmem`), starts at the byte after `putbufwpos` (the stock printf stores after a pre-increment), and prints text only (the log driver's copies bring binary header bytes). | 0026 | `modadmin-keep-messages` | `modadmin -K` (root) sets `prt_where`'s bit 0 (PRW_BUF) through the namelist and `/dev/kmem`, so every kernel message is kept in `putbuf` as well as going to the console. | 0027 | `image-limit-256k` | `dlm_maximage` is 256 KiB, not 2 MiB (C3-1 §6, version 4): the core's own allocations for a module are `KM_SLEEP` and grow with it, and U4 found that a running box gives one request at most 256 KiB, a larger `KM_SLEEP` one never returning. `lf_hashload`'s refusal of a file at the limit, a silent `ENOMEM` before, is `ENOLOAD` with the console line `its file is over the limit`. | 0028 | `str-open-level4-comment` | Comment only (`dlm.o` unchanged): `dlm_str_open` says that the stock `qattach()` calls a STREAMS open at level 4 (SR 0x2400) and the core leaves it, so a level-2 interrupt the open raises is taken only after it returns or while it sleeps (C3-6 §1.3; S3-44-3). | no (ours) |
| 0029 | `no-sleep-mode` | 30 §2 patch 3 (S4-02). The root pass runs at level 7 with the clock stopped (U1), where nothing may sleep. `dlm_nosleep`, which the root pass sets (S4-04), makes `dlm_zalloc` ask `KM_NOSLEEP` and refuse a request over 1 MiB (`DLM_NOSLEEPMAX`). Every allocation on a load path checks for 0, and the load fails with `ENOMEM` and one console line, leaving the kernel as it was; a module another load holds is `EBUSY` instead of a wait. Outside the mode nothing changes. The state harness fails each allocation of a load in turn and checks that nothing is left behind. | not yet |
| 0030 | `halt-pass` | 30 §2 patch 11 (S4-07). The wrapper's halt entry was filled by the macros and never called. `dlm_halt()` runs each settled module's halt entry, newest first, once, so a board that can interrupt or write memory is stopped before the kernel halts or reboots (M-HALT1), and returns how many ran. The kernel calls it from `mdboot`, before `haltsys` or `rtnfirm`, for uadmin's `A_SHUTDOWN` and `A_REBOOT` only, never from panic or the keyboard reset (the port's records, OQ-30.5). An entry that is not code is named and skipped. | not yet |
| 0031 | `block-rows` | 30 §2 patch 7 (S4-06). The core refused any driver with `drv_bcount`; the ramdisk (block major 20) needs a block row. A driver may have consecutive block majors, each registered to it (`b:` in the registry), with or without character rows. The block switch has no first-open trampoline, so the row is filled when the module links and only a pinned module may have one. The row must be empty (every routine `nodev`, no flag set) and the entries module code or 0 (0 is `nodev`). A block row that cannot link puts the driver's character rows back, and a failed load puts the row back. The `bdevsw` layout is measured (`DRV_BDEVSW`, `DRV_BMAJOR`, `BD_NFN`, `BD_FLAG`), which adds ABI names: the stage-4 kabi minor `k46.1.1` / `k30.1.1` (`abi/<line>/abi-<kabi>.txt`). | not yet |
| 0032 | `sd-register` | 30 §2 patch 8 (S4-03), contract C4-1 §3. A root-class disk controller registers each board from its `_load`: `sd_register(queuefn, c, base, name, rank)`. The entry waits in the core's table of four until sd's first open takes it (`dlm_sd_close`) and ranks it with the floor's controllers; registration is then closed (`EBUSY`). The rank must be the class the module declares in `.moddata` (`rank=z3660`, `zorro`, `mobo` or `ide`, now parsed); a fifth is `ENOSPC`. A `_load` that fails after registering leaves no entry: the backstop sweep removes it. `sd_register` is a DDI name of minor 1. | not yet |
| 0033 | `arena-load-path` | 30 §2 patch 2 (S4-01), contract C4-4 version 2 §4. `dlm_load_mem(name, p, len, bss)` loads a root-class module from its file bytes in the arena: no path, no file read, no hash (the root pass checks the CRC-32 against the directory). Its allocated PROGBITS sections are relocated where they lie, each at an offset that is a multiple of its alignment, at most 16. NOBITS and COMMON go into the zeroed tail boot2 reserved behind the file, and a layout larger than the reserve is `ENOLOAD`. The image is that one span, so the range checks stay as they are; nothing is allocated for it or freed. Root class is accepted only from the arena, and only root class there; a dependency must already be linked. | not yet |
| 0034 | `marc-root` | 30 §3, §2 patch 16's root half (S4-04), contract C4-4 §4. `dlm_marc_root()`, the kernel's hook in `rth1_mountroot` before `rth1_apply`, walks the arena directory in order in no-sleep mode (level 7, the clock stopped, U1). Then `dlm_load_mem`. `ENXIO` (no such board) is silent, any other error one line. In safe mode only the safe-mode members (flag 0x4) link. `dlm_arena_init` keeps the arena's address; `dlm_crc32` gives the core the loader's CRC-32. | 0035 | `marc-root-match` | Contract C4-4 version 3 §4 (S4-10's other half). boot2 places every root-class record and selects none, so the root pass reads each record's `match=` keys from the manifest copy and checks them with `marc_post`'s platform matcher (`zorro:MMMM:PP` against the board list, `mobo:` and `always` always).
